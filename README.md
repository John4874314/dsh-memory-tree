---

给 DeepSeek Harness 的双树长期记忆。任务树按工作目录各一棵，记住「这里做过什么」；习惯树全机一棵，记住「你是什么样的人」。上下文断裂或换新会话时，沿树三跳找回背景，用几百 token 代替整段历史重放。

## 为什么是两棵树

|  | 任务树 TASK | 习惯树 HABIT |
|---|---|---|
| 数量 | 每个工作目录一棵 | 全机唯一一棵 |
| 位置 | `<工作目录>/.memory-tree/` | `$DSH_HOME/memory-tree/.memory-tree/` |
| 收什么 | decision / deadend / fact / task / issue / constraint | preference 为主 |
| 树干 | 领域名，动态创建 | 固定「用户习惯」 |

两棵树共用同一套数据结构和引擎，唯一差别是宿主路径——所以双树只比单树多几十行。

## 四个机制（这才是长期记忆的来源）

1. **分级摘要**：叶摘要是模型写的，枝/干的 `digest` 由代码把子节点标题拼接生成，幂等、可重建、token 稳定。
2. **索引与正文分离**：树里只有 `summary / keywords / pointer`，正文永远在 `logs/YYYY-MM/*.md`，按 `#L12-L30` 锚点按需读。
3. **按需展开**：检索先返回摘要层（不读正文），确认归属后 `memory_open` 才探原文。单次检索默认 3 条/树，为 token 预算服务。
4. **重要度调度**：半衰期公式决定冷热层，`due_at` 决定什么时候该复习。

## Agent 工具

| 工具 | 何时用 |
|---|---|
| `memory_grow` | 任务边界写入：阶段完成、决策拍板、上下文将满、用户明确要求记下来。单批 1-8 条 |
| `memory_search` | 「上次做到哪了 / 之前定的方案 / 那个 XX 是什么来着」 |
| `memory_open` | 确认需要逐字细节，顺着指针读原文 ±10 行 |
| `memory_brief` | 会话将满、要换新会话、接手别人的任务 |
| `memory_maintain` | `diagnose` 自测诊断、`delete/restore` 软删还原、`purge`、`orphans`、`rebuild`、`merge`、`status` |

## 判定规则（交给模型，但规则写在工具描述里）

**值得记**：decision（拍板+理由+舍弃的备选）、deadend（试过不行，极省下游时间）、fact（可复用结论）、task/issue（未完成+阻塞点，必填可执行的 `next_hint`）。

**不记**：寒暄、纯确认语、工具调用噪声、重复表述。

**闸门**（由引擎强制，不合格直接拒）：单批 ≤8 条；`title` ≤20 字；`summary` ≤60 字且自足；`task/issue` 必须有 `next_hint` 且不能是「继续推进」这类空话；`content` 非空；`keywords` 1-5 个。

## 可视化面板

侧栏树形图标进入。左右并排两棵树，从底部的树干向上长枝、枝顶扇出叶；冷热用色点区分（热绿/温黄/冷灰），疑似重复是虚线琥珀描边。右侧是选中节点详情（摘要、关键词、指针、可展开日志原文）、自测诊断（待复习 / 疑似重复 / P0 掉出热层 / 阻塞中）、交接快照、回收站。

删除走三选一弹窗（连子树删 / 仅删本节点子节点上移 + 备注），进回收站 30 天可逐字段还原，**日志原文永远不跟着删**。

## AI 分组与起名

一个枝上的叶子超过 6 个时，树会显得很宽。这时可以交给模型按语义归组，把一串"看起来差不多"的叶子收成几个有名字的组。

**两个入口，用途不同：**

| 入口 | 位置 | 作用 |
| --- | --- | --- |
| **整树分组** | 树面板工具栏的 `✧` | 扫描整棵树，凡是子节点超过 6 个的枝都分一次组 |
| **单桶起名** | 序号分桶右侧的「起名」 | 只处理这一个桶 |

**整树分组**适合一次收拾干净。**单桶起名**适合整树分组漏掉或失败的场合，也允许模型按内容重新划分成员——你认为这 6 条该拆成两组，它就拆。

**分桶是什么？** 分组没跑之前，超额的子节点会按 6 个一组切成 `1–6 组`、`7–12 组`。这只是个占位，没有任何语义。点「起名」后它会被真实组名替换，比如「环境变量」「删除风险」。

**花多少额度？** 每次调用约 0.2 分钱（输入 ~1000 token、输出 ~50 token）。一棵 60 条记忆的树全量分组约 0.7 分。给所有分桶逐个起名约 1.7 分。

**关掉或换模型：** 设置面板 →「AI 分组」。可以整体关闭（只保留序号分桶），也可以指定用哪个模型。

默认是**跟随当前会话**——你正在对话用哪个模型，分组就用哪个。想省钱可以钉一个小模型；留空则保持跟随。下拉只列你实际在用的 provider，不会铺出上百个模型。

> 分组失败不影响树本身。模型返回格式不对时只是跳过，叶子仍按序号分桶展示。

## 数据落点

```
<工作目录>/.memory-tree/
├── tree.json          索引层
├── tree.json.bak      每次写前自动备份
├── recycle.json       回收站快照
├── config.json        可覆盖的默认参数
├── .lock              写锁
├── index/             倒排索引 + touch.log 命中流水
├── staging/           锁冲突时的暂存批次
├── briefs/            交接快照历史
└── logs/YYYY-MM/*.md  正文（事实层）
```

## 与规格书的两处刻意偏离

1. **分层计入 access_count**。规格书的分层只看 `base_score`，而叶的 `importance` 默认 0.6，`base_score` 永远够不到 0.7 的热层阈值——「越访问越热」在原公式里不成立。这里把访问次数并入 `score`，让常用的东西真的留在热层。
2. **检索命中不写树**。规格书要求命中即 `access_count+=1` 并立即保存，这与「读操作永不加锁」直接冲突，且多会话并发时会打架。改为写入无锁追加的 `index/touch.log`，下次任意写操作时批量折进树。

另外补了规格书缺的一块：**复习调度**。衰减只回答「现在多重」，`due_at` 回答「什么时候该复习」，诊断面板的「待复习」就是它的输出。

## 已知边界

- `.memory-tree/` 落在工作目录内，会出现在 `git status` 里。需要的话自己加进 `.git/info/exclude`。
- 工作目录被删除或移动，任务树和日志一起没。习惯树在 `$DSH_HOME` 下不受影响。
- 缩写型 JSON 输出、默认 top3 都是为了压 token；调大 `topn` 会明显增加单次开销。

## 卸载

插件管理里移除即可。记忆数据留在各自目录的 `.memory-tree/` 和 `$DSH_HOME/memory-tree/` 下，不会自动删除——想彻底清掉需要手动删这两个位置。

## 从历史会话建树

顶栏新增三个按钮，用来把**已有会话**变成记忆树：

| 按钮 | 作用 |
| --- | --- |
| `📥` | 导入工作区 —— 扫描归档会话，为还没有树的工作区建一棵任务树 |
| `🧠` | 导入习惯树 —— 从会话里提炼长期偏好，并入全机唯一的习惯树 |
| `♻` | 整树回收站 —— 被删除的整棵树在这里等待还原 |

### 两种提炼方式

- **规则提取**：离线、瞬时、零成本。只捞取明确写下的决策、约束、死路、待办、问题。颗粒较粗，但可预测。
- **AI 总结**：调用当前会话的模型，按 40 条消息一段、最多 8 段逐段概括。文字更通顺，但消耗额度，且结果未必更好；超出上限的部分仍由规则提取兜底。

### 数据来源

会话日志位于 `$DSH_HOME/sessions/--<编码路径>--/session-*/session.v4.jsonl.zstd`。

两个必须知道的细节：

1. 这些文件是**多帧 zstd**（一次 flush 一帧），Node 自带的 `zstdDecompressSync` 只解第一帧。`lib/session-log.js` 自行按 magic 走帧边界。
2. 目录名是**有损编码**：`--E-dsh-workspace-project-dsh-memory-tree--` 里的连字符无法区分路径分隔符。工作区归属一律取自会话头部记录里的 `cwd` 字段。

### 整树删除与还原

- 删除是把整个 `.memory-tree` 目录**移动**到 `$DSH_HOME/memory-tree/trash/`，不是逐个删节点——还原因此是精确的。
- 工作区会保留一个**空壳**并标注「已删除 · 可恢复」，避免误以为彻底丢失。
- 超过 `recycle_days`（默认 30 天）的条目由 `purge` 清理；`days=0` 表示永久保留。
- 还原时若目标已有活树：先选**覆盖**或**合并**，再二次确认。覆盖会把现有树也移入回收站，所以换血同样可逆；合并会为导入节点加后缀 id，不会与现有节点冲突。
